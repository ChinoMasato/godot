# 光の筋と風揺れの GPU 比較（B-719／B-720）

```powershell
python ai_loop/windows/effects_gpu.py ../effects-output --godot ../godot/bin/godot.windows.editor.x86_64.console.exe
```

実行場所はこの worktree のルート。通常の checkout で使う場合は `--godot bin/godot.windows.editor.x86_64.console.exe` を指定する。Python と Pillow が必要。Linux でも `--godot` にその環境のエディタを指定して Vulkan で実行できる。

出力は `report.json`、各ケースの PNG とログ、`comparison.png`。コマンドは JSON を標準出力に1行返し、進捗を標準エラー出力に書く。描画の異常終了、ERROR、タイムアウト、保存失敗、比較条件未達は終了コード1になる。

最初の失敗で撮影を停止し、ログを残す。Windows は console ランチャーの隣の実行本体を直接起動してタイムアウト時に終了できるようにする。撮影は上限60fps。GPUの負荷を抑えながら各フレームのGPU処理時間を測る。

風なし／通常の風（0.12 m）／強風（0.8 m）を0.4秒と1.2秒で比較する。毎回同じ時刻を撮るため、この試験のマテリアルのコピーだけで `TIME` を時刻指定用 uniform に置換する。加えて `wind_live` は製品のシェーダーをそのまま動かし、同一プロセス内の60フレーム目と最終フレームを比較する。後者は実時間に依存するため、実行ごとに変化率は異なる。

風なしの画像が静止し、通常の風で変化し、強風で変化する画素が増え、光の筋が表示され、製品の時間駆動でも動くことを確認する。変化率はRGBの最大差が8を超えた画素の割合。見た目の美しさや物理的な正確さを自動判定するものではない。

形状は手続き生成の円錐3本、床とライト。風揺れの根元基準に合わせて高さ1.5 mとし、モデル画像の取り込みは不要。GPU時間は60フレームの準備後の中央値。ポスト効果を含まず、この小さな検証シーンでの値なので、ゲーム全体の速度とは区別する。
