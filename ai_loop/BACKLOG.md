## Phase 12（リッチ化 — Blender 連動と画面密度）— 2026-11-18 オーナー指示
最適化の対象は人間の GUI 操作ではなく、**AI エージェントが CLI／構造化出力だけを使ってリッチなゲームを作りやすいこと**（2026-11-18 オーナー追加指示）。全項目は「エージェントが短い指示から、少数回の反復で予算内のリッチさに届くか」で測る。レポート類はエージェントの「目」として、要約＋掘り下げの形で返す。
- [ ] B-1201 Blender ブリッジ: headless の Blender（bpy スクリプト実行）→プレビューレンダー→GLB 書き出し→プロジェクト配置を ai_loop の1コマンドにする。Blender 本体は同梱しない（GPL のため、連動は外部ツールとしての橋）。判定: スクリプトから小物モデルを1つ作り、プレビュー PNG と GLB がプロジェクトに置かれること。

- [ ] B-1203 `UZUScatter` 小物の散布: 面の上に小物を散布する C++ 静的 API（密度パラメータ＋シード固定で再現可能、MultiMesh でまとめて描く、除外エリア対応）。判定: 同じシードで同じ配置になることと、個数・密度の単体テスト＋全テスト pass。
- [ ] B-1204 リッチ度レポート: シーン／画面のトライ数・ドローコール・テクスチャメモリ・小物の密度を構造化出力（UZU_RESULT）し、予算（上限値）との合否を出すコマンド。判定: 見本シーンで数値が出て、予算超過のシーンを fail と判定できること。
