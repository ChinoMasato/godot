# 構造化フィードバックの形式（B-601, 2026-11-17）

プレイヤーの感想を、作者と AI が直すための情報と、作者に届ける言葉に分ける形式。

## 設計上の決まり

- **点数化しない。** 星・点数・好き嫌いの段階を持たない。形式に `rating`・`stars`・`score` などの項目があれば、変換ツールは受け付けない。
- **構造化するのは直すための情報だけ。** 種類、場所、再現の手順、期待と実際。BACKLOG の課題はこの項目だけから作る。
- **感想の本文（`message`）は「贈り物」として、そのまま作者に届ける。** 変換ツールは本文を要約・言い換え・分類に使わない。BACKLOG の課題には、本文の代わりに「どの感想か」の番号だけを書く。
- **個人を追跡しない。** プレイヤーの ID や連絡先は入れない。名乗りたい人は `signature`（自由記入、任意）に書ける。それも本文と同じく作者にだけ届く。

## 1件の形式（JSON。ファイルには1件ずつ並べた配列か、JSON Lines で入れる）

| 項目 | 必須 | 型 | 意味 |
|---|---|---|---|
| `v` | ○ | int | 形式の版（1） |
| `kind` | ○ | string | `stuck`（詰まった）／`bug`（不具合）／`idea`（アイデア） |
| `message` | ○ | string | プレイヤーの言葉。そのまま作者に届ける |
| `where` | | object | 場所。`scene`（res://...）、`checkpoint`（直前に着いた ID）、`cell`（[x, y, z]、テレメトリ B-301 と同じ格子）のどれか1つ以上 |
| `build` | | string | ゲームの版 |
| `steps` | | [string] | bug の再現の手順 |
| `expected` | | string | bug: こうなると思った |
| `actual` | | string | bug: 実際はこうなった |
| `signature` | | string | 名乗り（自由記入）。作者にだけ届く |

例は `sample_feedback.json`。

## BACKLOG への変換（to_backlog.py）

`ai_loop/feedback/to_backlog.py <feedback.json> [--prefix F] [--gifts gifts.md]`

- 同じ種類・同じ場所（scene・checkpoint・cell）の感想を1つの課題にまとめ、件数を付ける。
- 種類ごとの判定（BACKLOG の「判定:」に入る）:
  - stuck: 自己検証プレイ（B-303）やテレメトリ（B-301）で、その場所の死亡・停滞が減ること。
  - bug: 再現の手順で再現しなくなること。手順がない bug は「再現手順の確認から」とする。
  - idea: 作者が採るかどうかを決める。AI は作者の承認まで実装しない（設計の判断なので）。
- 出力:
  - BACKLOG の形式の行（`- [ ] F-001 ...`）を標準出力に出す。
  - `--gifts` を付けると、本文をそのまま並べた作者向けのファイルを書く。番号は BACKLOG の行から参照される。
