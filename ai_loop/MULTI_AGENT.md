# マルチエージェント開発プロトコル

複数の AI エージェント（Claude Code／Codex／Muse）が同じソースコードを同時に開発しても、衝突と破壊が起きないための運用規則。主ツールは Claude Code（千野の決定、2026-11-17）だが、規則はツール共通。

## 原則

1. **1エージェント = 1 BACKLOG項目 = 1 worktree = 1ブランチ。**
   ブランチ名は `agent/<項目ID小文字>-<担当名>`。メインチェックアウト（`ai-native`）で直接編集しない。
2. **担当と編集範囲を先に宣言する。** 着手前に `CLAIMS.md` へ「項目／担当／ブランチ／触るパス／状態」を1行書く。宣言のない編集はしない。
3. **所有権はサブシステム単位で分ける。** `core/`、`scene/`、`servers/`、`drivers/`、`modules/<モジュール名>/`、`editor/`、`platform/`、`tests/` が分割の目安。同じサブシステムに2エージェントが入る場合は、パスをさらに割って両方を CLAIMS に明記する。
4. **共有ファイルは統合担当だけが触る。** `version.py`、`SConstruct`、プロジェクト形式に関わる中核、`ai_loop/` の運用ファイル（BACKLOG／LEDGER／CLAIMS／本書）。担当項目で必要になったら、自分で書き換えず CLAIMS に申し送りを書く。
5. **ビルドは直列化する。** `build_locked.sh`（flock で排他）経由でのみビルドする。この VM は同時ビルド禁止（実効1.5コア）。ローカル PC や CI でも、統合前の確認ビルドは1つずつ回す。
6. **記録は分離する。** 各エージェントは `iterations/<日付>-<項目ID>-<担当名>.md` に自分の記録を書く（1イテレーション1ファイルなので追記衝突が起きない）。`LEDGER.md` への追記はマージ時に統合担当が行う。
7. **マージ規律。** agent ブランチは、最新の `ai-native` を取り込んだうえで増分ビルド＋全テスト pass を確認してからマージする。fail したブランチはマージしない。競合の解決は「後からマージする側」が行い、相手の変更意図を変えた場合は iterations の記録に明記する。
8. **統合担当（リード）。** 人間（千野）または指名された1エージェント。CLAIMS の調整、`ai-native` へのマージ、LEDGER 追記、上流 Godot の追随マージを担当する。リード以外は `ai-native` に push／マージしない。

## 手順

```sh
# 1. worktree とブランチを作る（メインチェックアウトで実行）
ai_loop/agent_start.sh B-101 claude-a

# 2. CLAIMS.md に担当を宣言する（メインチェックアウト側で編集し、リードが取り込む）

# 3. worktree に移って実装する
cd ../wt-b-101-claude-a
#    … 小さい差分で実装し、テストを足す（AGENTS.md のループ規則に従う）

# 4. 仕上げ: ロック付きビルド＋全テスト
ai_loop/agent_finish.sh

# 5. iterations/ に記録を残し、ブランチをコミットしてリードに渡す
```

## ツール別の注意

- **Claude Code**: ルートの `CLAUDE.md` が `AGENTS.md` を取り込み、本書への参照を含む。サブエージェントは探索専用に使い、編集は親が自分の worktree で行う。
- **Codex**: `AGENTS.md` を読むため同じ規則が効く。worktree の作成は `agent_start.sh` を使うこと。
- **Muse（この VM）**: 同じ規則に従う。この VM ではビルドが特に重いので、並行作業は「編集と調査」までに留め、ビルドはロックに集約する。
