## 内容

- **エンジン**（`scene/3d/uzu_picture.{h,cpp}`、新規）: `UZUPicture : Node3D`。試作 `ai_loop/prototypes/picture/uzu_picture.gd` を、同じ手順・同じ既定値のまま C++ に移した。
  - プロパティ:
    - `spec`（Dictionary）
    - `spec_path`（JSON ファイル。`spec` が空のときに読む）
  - メソッド:
    - `build()`: 統計の Dictionary を返す（ok、grid、torn_triangles、backdrop_fill_ms、backdrop_filled_share、rain、ember_sources、fog_sheets、lightning、lights、image_size）。
    - `get_stats()`、`is_built()`
    - `place(pixel, depth)`、`depth_at(pixel)`、`point_at(pixel)`: 絵の画素 → 3D 位置。エージェントが自分のノードを絵の中に置くため。
  - ツリーに入ると組み立てる。PROCESS では、カメラの漂い、稲光、ライトのゆらぎを動かす。
  - 組み立てたノードには meta `_uzu_picture_built` を付ける。作り直すときはそれだけを消し、利用者の子ノードは残す。
  - 試作のシェーダー2本（起伏、霧の板）は、そのまま文字列で埋め込んだ。
  - 穴埋め（`min_filter`、`fill_behind` の pull-push）は、テストとツールのために public static にした。
  - 雲のノイズは、FastNoiseLite（modules/noise）の代わりに、自前の周期的な値ノイズにした。scene/ から modules/ への依存を作らないため（見た目の確認はローカル担当）。
  - `register_scene_types.cpp` に登録。ドキュメント `doc/classes/UZUPicture.xml`（新規）に、仕様のキーを全部書いた。
- エディタの GUI は作っていない（2026-11-18 の方針）。シーンには、`[node type="UZUPicture"] spec_path = "res://picture.json"` と書くだけで使える。エージェント向けのコマンドは B-904 で扱う。

## 確認

- 単体テスト: `tests/scene/test_uzu_picture.cpp`（新規、4件）。
  - 合成の絵（320x200、手前に赤い塔）と深度を一時フォルダに書き、仕様から組み立てる。
    - 統計を確かめる: ライト2つ、霧の板2枚、稲光あり、火の粉の出どころ2つ、裂けた三角形が 0 より多い、背景の穴埋めの割合が 0 より大きい。
    - 格子の大きさを確かめ、三角形の数が「格子×2 − 裂けた数」になることを確かめる。
    - 子ノードがあることを確かめる。
    - ライトは、指定した画素の面のすぐ手前（0.93倍）に置かれる。
    - カメラの画角は、overscan の分だけ 38 より小さい。
    - Look には、ポストエフェクトの compositor が付く。
    - 作り直しても、子ノードは増えない。
  - `place`／`depth_at`: 画面の中心は、near／far の距離でカメラの正面に来る。隅は画角どおりの位置に来る。深度の値は描いた値と合う。手前の塔は、奥の空より近い。
  - 読めない仕様では ok=false と誤りの文が返り、何も作られない。
  - `min_filter` と `fill_behind`: 手前の物が塗りつぶされ、穴の真ん中に背景の色が入る。
- 全テスト: **1505件中 1505 pass**（4件増えた）。ビルドの警告: なし。clang-format: pass。
- 実地の確認（`uzu.py engine import` → `look shot`、lavapipe）:
  - 960x540 の合成の夜景（窓のある塔、地面、星）に、雨、火の粉、霧、ライト2つ、月を付けた仕様で確認した。
  - 撮影は通り、誤りはなかった。窓の光、雨の筋、塔の上の火の粉、塔の輪郭の手前／奥の分離が写った。
  - `engine run` も ok で、誤りは 0 件だった。
- `uzu.py selftest all`（engine／selfplay／tools）: ok。
- ドキュメント: UZUPicture.xml に誤りはない。
  - `make_rst.py` は全体で13件の誤りを出すが、これは今回より前からある。
  - そのうち1件は、`UZUPaletteDither.xml` の get_dither_threshold の `[code]` が閉じていないもの。範囲外なので触っていない。
