  - 判定: 見本 UI で数値が出て、貧弱な UI を指摘できること。

## 内容

- **`ai_loop/ui_report_probe.gd`**（新規、autoload）と **`uzu.py look <project> ui-report --scene res://ui/x.tscn [--resolution 1280x720] [--shot out.png]`**:
  - プロジェクトの写しで、UI のシーンを headless で動かす。レイアウトと文字の組版に GPU は要らないので、CI でも動く。
  - 数フレーム後に、表示中の Control をすべて測る。
- **要約**:
  - Control・パネル・ボタン・文字の数と、文字数。
  - 最小の文字サイズ、階層の深さ。
  - 画面の覆い率（64×36 の格子で、パネル・ボタン・リスト・タブ・バーが覆う割合）。
  - パネルと画面の端の最小距離、見た目が既定のままの部品の数。
- **問題**（それぞれに直し方の `fix` が付く。1つでもあれば ok=false）:

  | 種類 | 条件 |
  |---|---|
  | `small_text` | 14 px 未満（720p 基準） |
  | `text_overflow` | Label が、与えられた幅や親をはみ出す。Godot の Label は文字より小さくならず、黙って広がるので、offsets の幅と実際の幅を比べる |
  | `small_button` | 高さ 44 px 未満（タッチ操作。B-1004／B-1306 向け） |
  | `no_margin` | 一番外のパネルが、画面の端から 8 px 未満 |
  | `overlap` | 一番外のパネル同士が重なる |
  | `off_screen` | 画面の外にはみ出す |
  | `unstyled` | テーマのない、既定の見た目のパネルやボタン |

- **ヒント**: 文字がない、覆い率が 5% 未満（メニューなら少ない）や 60% 超（ゲームが見にくい）、パネルでまとめていない平たい UI。
- 一番外のパネルの一覧（矩形と子の数）も返す。直す場所を特定するため。
- **headless での注意**（直したもの）:
  - headless の窓は `--resolution` を無視して 64×64 になり、レイアウトが崩れて測れなかった。プローブが、指定した大きさを窓に設定するようにした。
  - プローブのスクリプトが壊れていると、シーンが終わらずに止まった。`--quit-after` で、必ず終わるようにした。
- 見本: `ai_loop/look_samples/specs/poor_ui.tscn`（わざと貧弱にした画面）。MCP: ui_report。

## 確認

- `uzu.py ui` で作った HUD（B-1301／B-1302）:
  - ok=true、問題 0。
  - Control 20、パネル 3、ボタン 2、文字 8（75 字）、最小 20 px、深さ 4、覆い率 29.3%、端から 20 px、既定のまま 0。
- 貧弱な画面:
  - ok=false で、6種をすべて指摘した: small_text（11 px）、small_button ×2、no_margin（0 px）、overlap、text_overflow（100 px の枠に長い文）、unstyled ×4。
  - 並べた画像: `ai_loop/look_samples/compare/b1305_ui_report.png`。
- `uzu.py selftest engine` に2項目を足した（貧弱な画面で6種、作った画面では既定のまま・重なり・端・はみ出しが 0）。
- `uzu.py selftest all`（engine／selfplay／tools）: ok。`mcp_server.py --self-test`: ok。エンジンのコードは変えていない。
