# B-301 プレイテレメトリの形式定義 — claude (2026-11-17)

- ブランチ: ai-native に直接反映。
- BACKLOG B-301: 詰まり（同じ場所での死亡・停滞の集中）、離脱点、クリア到達を、作者と AI が読める JSON で定義する。個人を追跡しない（コミュニティ単位の集計が既定）。

## 内容（すべて ai_loop/telemetry/、エンジン本体の変更なし）

- `FORMAT.md`: 形式の定義。
  - イベントログ（JSON Lines）: start／checkpoint／death／stall／clear／quit の6種類。共通の項目は v・session・type・frame・time・scene・cell。
  - レポート（JSON）: sessions・cleared・clear_rate・deaths・stuck_points（詰まり）・checkpoints（到達）・drop_off（離脱点）・fps。
  - 個人を追跡しない決まり: 識別子は使い捨ての乱数 session だけ。ユーザー ID・端末 ID・IP・日時は入れない。時間はプレイ開始からの経過だけ。レポートにはセッションごとの行を出さない。
- `telemetry.gd`: 記録用の autoload（`UZUTelemetry`）。
  - ゲームは checkpoint／death／clear を呼ぶ。
  - グループ `uzu_player` のノードから、位置の格子（cell）と停滞（同じ格子に 10 秒）を自動で記録する。
  - session は、ゲームが乱数の種を固定していても毎回変わるように、専用の乱数で作る。
- `report.py`: ログ（ファイルかフォルダー）を集計してレポートを作る。標準ライブラリだけ。途中で切れた最後の行は飛ばす。
- `sample_logs/`: 3プレイ分のサンプルログ。

## 確認

- `report.py --self-test`（サンプルログ3件）で、すべて期待どおり。
  - 3セッション、クリア1件（clear_rate 0.333）、死亡4件。
  - 詰まりの先頭: cell [100,0,0]、死亡3・停滞1、2セッション。死亡1件だけの場所は詰まりに出ない。
  - 到達: cp1 が3件、cp2 が2件。離脱点: cp1 と cp2 で1件ずつ。
  - fps: 平均 58、最小 56。
  - レポートに session の値が出ない。
- サンプルゲームの実際のログからもレポートができた（B-303 の sample_game を `telemetry.gd` 入りで実行した）。
  - start → checkpoint ×3 → death → clear → quit がログに出た。
  - それを report.py に渡すと、形式どおりのレポートになった。
- 全テスト: C++ の変更はないので、B-103 と同じバイナリで 1481/1481 pass。
