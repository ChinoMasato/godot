# A-3（Q5、仮、B-102 相当）localhost の名前解決を RFC 6761 に合わせる — claude (2026-11-17)

- ブランチ: claude/uzu-engine-briefing-rrno7b
- 承認: COORDINATION.md Q5（順序の承認）と、オーナーによる案aの選択（2026-11-17: 「案aで進めて」）。
- 課題: `[IP] resolve_hostname` が、`/etc/hosts` に `::1 localhost` の無い環境で fail する（B-001 で見つけた環境起因の fail）。原因は、名前解決を OS の getaddrinfo にそのまま任せていること。RFC 6761 6.3 は「localhost は必ずループバックに解決されるべき」と定めている。

## 変更概要

- `core/io/ip.cpp`: `_resolve_localhost_fallback()` を追加し、同期（`resolve_hostname_addresses`）と非同期（解決キュー）の両方の経路で、OS の解決のあとに呼ぶ。
  - **OS の解決が空だったときだけ**働く（OS が答えを返す環境では、これまでと同じ答えのまま。振る舞いの変化を最小にするため）。
  - 対象は名前 `localhost` だけ（大文字小文字は区別しない）。IPv4 → 127.0.0.1、IPv6 → ::1、ANY → 127.0.0.1 と ::1 の順。
  - `*.localhost` と末尾のドット（`localhost.`）は扱わない。環境によっては DNS への問い合わせが起き、テストがネットワークに依存してしまうため。
  - 公開 API（関数のシグネチャ）は変えていない。
- `tests/core/io/test_ip.cpp`: 2件を追加。
  - `[IP] Localhost names resolve to loopback`: 大文字小文字の違う `LocalHost` で IPv4／IPv6、`localhost` の ANY がループバックになること。
  - `[IP] Queued localhost resolution`: 非同期（キュー）の経路で `LOCALHOST` の IPv6 が ::1 になること（キャッシュを通らない綴りを使う）。
