## 内容

- **`ai_loop/ui_tool.gd`**（新規。headless の SceneTree スクリプト）: 1つの JSON 仕様から、UI のシーン（Control ツリー）を組み立てて保存する。
  - 種類（短い名前 → Godot のクラス）:
    - Screen（全画面の根）、Panel（PanelContainer）
    - VBox／HBox／Grid／Margin／Center／Scroll
    - Label、RichText（BBCode）、Button、Bar（ProgressBar）
    - Image（TextureRect）、Color（ColorRect）、Spacer
  - **置き方**:
    - コンテナの外では、`anchor`（四隅、上下左右の中央、中央、全面、上下左右の帯）と、`offset`（端からの距離）、`size` で置く。
    - 右や下に寄せた物は、内側に向かって伸びるようにした（grow を設定）。
    - コンテナの中では、`min_size` と `expand` を使う。コンテナの中で anchor を書くと、誤りとして教える。
  - **テーマ**: 1つの Theme 資源をシーンの根に持たせる。
    - フォント（`font` で res:// のフォントも指定できる）、文字の大きさ、文字の色。
    - パネル: 角丸、枠、影、余白（StyleBoxFlat を手続きで作る）。
    - ボタン: 通常、ホバー、押下。
    - バー: 背景と、埋まった部分。
    - アクセント色。
    - 部品ごとに `style`、`font_size`、`font_color`、`align` で上書きできる。
  - 根は、クリックを下に通す（ゲームの上に重ねる HUD のため）。
  - **仕様の誤りは、場所付きでまとめて返す**: 知らないキー（その種類で使えるキーの一覧付き）、知らない種類、知らない anchor、色の形式、コンテナ内での anchor など。誤りがあるときは、何も保存しない。
- **`uzu.py ui <project> --spec ui.json [--shot out.png [--over res://game.tscn]]`**:
  - `--over` を付けると、ゲームのシーンの上に UI を CanvasLayer で重ねた、一時的なプレビューシーンを作って撮影する。プレビューシーンは、撮影後に消す。
  - MCP: ui_build。
- **仕様の例**: `ai_loop/look_samples/specs/hud.json`（『灯りの欠片』風）。
  - 左上: 名前、レベル、HP／MP のバー。
  - 右上: 欠片のカウンター。
  - 下: 話し手、台詞、ボタン2つのダイアログ。

## 確認

- 例の仕様を、B-1207 で作った村（村に B-1208 の village_rich を当てたもの）の上に重ねて撮影した（lavapipe、1280x720）。
  - パネル3つ、バー2つ、ボタン2つ、ラベル6つ。
  - 角丸、金の枠、影、日本語の文字、右上と下の帯への寄せが、どれも意図どおりに写った。
  - 画像: `ai_loop/look_samples/compare/b1301_hud.png`。
- **日本語**:
  - この環境では、OS のフォント（WenQuanYi）への自動フォールバックで表示された。
  - Web 版には OS のフォントがない（B-1003 の文字化けの教訓）。テーマの `font` で、フォントを同梱して指定する作法にした。サブセット化は B-1303 で扱う。
- `uzu.py selftest engine` に2項目を足した:
  - 小さな仕様から画面ができる。パネル2つで、Status／HP／OK のノード、StyleBoxFlat、下寄せのアンカーが保存される。
  - 誤りが3つある仕様（anchor `middle`、Button の `txt`、コンテナ内の offset）では、3つとも場所付きで返る。
- `uzu.py selftest all`（engine／selfplay／tools）: ok。`mcp_server.py --self-test`: ok。
- エンジンのコードは変えていない。
