# B-306 歩調を合わせる制御の口（lockstep） — claude (2026-11-17)

- ブランチ: ai-native に直接反映（Q8 の承認による）。
- BACKLOG B-306（B-302 の R2・R3・R4・R7・R8）: 外部の AI が、観測を見ながら1ステップずつ入力を決めて遊べる口。

## 内容（エンジン本体の変更なし）

- `ai_loop/selfplay/control.gd`（autoload `UZUControl`）:
  - 各ステップの始めに、観測を1行（`UZU_STEP {json}`）で標準出力に出し、標準入力から次の命令を1行待つ。命令が来るまでゲームは進まない。
  - 命令: `frames`（進めるフレーム数）・`press`／`release`・`state`（`ノードパス:プロパティ` の一覧）・`image`（画面の保存先）・`reset`（シーンを読み直し、押しているアクションを離す）・`quit`
  - 観測: `frame`・`events`（前回からのテレメトリの出来事）・`state`（Vector は配列、ないノードは `{"error"}`）・`image`・`done`（クリアした）・`reset`・`ended`
  - ゲームが自分で終了したとき（サンプルはクリアで quit する）は、最後の観測を `ended: true` で出す。
  - `--uzu-seed` で乱数の種も固定できる（B-305 と同じ）。
- `ai_loop/telemetry/telemetry.gd`: 記録するたびに `event_recorded` シグナルを出すようにした。制御の口は、これで出来事を観測に入れる。ファイルへの記録は変わらない。
- `ai_loop/aiplayer.py`（標準ライブラリだけ）: Python のクライアント `Game`。
  - プロジェクトのコピーに autoload を入れて起動する（selfplay と同じく、プロジェクト本体は変えない）。
  - メソッド: `step()`・`observe()`・`reset()`・`close()`。`with` で使える。
  - `render=True` で、ソフトウェア描画で画面も取れる。
  - 終わったゲームに step すると、分かるエラーになる。

## 確認

- `aiplayer.py --self-test`: ok（約1秒）。
  - プレイヤーの位置（state）を読み、穴の手前でジャンプする簡単な方針で、サンプルゲームを死亡0でクリアした（cp1〜cp3 → clear、最後の観測は ended）。
  - リセット: 位置 [0, 0]・respawn_x 0 に戻る。ないノードはエラーとして返る。
  - ジャンプしない方針: 最初の穴で死に続け、死亡が観測の events に届く。
  - `frames: 10` で、ちょうど10フレーム進む。
- 画面: `render=True` で、640×360 の PNG が取れた（プレイヤーを追うカメラから、線と穴が見える）。
- `selfplay_selftest.sh`: ok（テレメトリの変更の後も、再現性と種の検査が通る）。
- 全テスト: C++ の変更はないので、B-103 と同じバイナリで 1481/1481 pass。

## 途中の失敗

- サンプルゲームはクリアした瞬間に自分で quit するので、クリアの出来事を含む観測が届く前にプロセスが終わった。終了時（`_exit_tree`）に最後の観測を出すようにした。
