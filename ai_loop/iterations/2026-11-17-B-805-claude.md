# B-805 ライトマップの焼き込みをエディタなしで — claude (2026-11-17)

- ブランチ: ai-native に直接反映（Q10 の承認による。エンジン本体の変更）。
- BACKLOG B-805: LightmapGI の焼き込みを、エディタの画面なしでコマンドから行う。

## 調べたこと

- `LightmapGI::bake` は、スクリプトから呼べるようにする登録がコメントアウトされていた。
- 焼き込みには2つの前提がある:
  1. 焼いた画像を保存して、エディタの取り込みの仕組み（`ResourceLoader::import`。EditorFileSystem が設定する）で取り込む。
  2. 描画装置（RenderingDevice）の上で計算する。
- そのため、エディタを起動しない `--script` での実行や、ヘッドレス（描画なし）の実行では焼けない。

## 内容

- **エンジン**（`scene/3d/lightmap_gi.{h,cpp}`）: `LightmapGI.bake(from_node = null, image_data_path = "")` をスクリプトから呼べるようにした。戻り値は BakeError。
  - 既定では、エディタの「焼き込み」ボタンと同じく、LightmapGI の親から焼く。
  - エディタの取り込みの仕組みがないときは、落ちずに `BAKE_ERROR_NO_LIGHTMAPPER` と説明のメッセージを返す。木に入っていないときは `BAKE_ERROR_NO_SCENE_ROOT`。
  - ドキュメント（doc/classes/LightmapGI.xml）に、このメソッドと、U.ZU Engine 独自であることを書いた。
- **ツール**: `uzu.py look <project> bake --scene res://x.tscn [--node Path/To/LightmapGI] [--prepare]`（MCP の lightmap_bake も同じ）。
  - エディタを描画ありで起動する（ディスプレイのない Linux ではソフトウェア Vulkan、Windows では GPU）。
  - 一時的なエディタプラグイン（`ai_loop/bake/`）が、次の順に処理する。
    1. ファイルのスキャンを待つ。
    2. シーンを開く。
    3. `--prepare` なら、PrimitiveMesh に UV2 を付ける（ライトマップに要る）。
    4. 焼き込み、シーンを保存して、結果を返す。
  - 終わったら、project.godot を元の内容に戻し、プラグインを消す。失敗しても戻す。
  - 結果: ok・error（BakeError の名前）・light_data・meshes・prepared・seconds。

## 確認

- 単体テスト: `tests/scene/test_lightmap_gi_bake.cpp`（新規）。
  - bake がスクリプトから呼べること。
  - 取り込みの仕組みがないと NO_LIGHTMAPPER（落ちない）。
  - 木の外では NO_SCENE_ROOT。
  - 木の中では本物の bake まで届く（保存先がないので NO_SAVE_PATH）。
- 全テスト: **1485件中 1485 pass**（1件増えた）。ビルドの警告: なし。clang-format: pass。
- `uzu.py selftest bake`（エディタを描画ありで起動する。重いので `all` には含めない）: ok（28秒）。
  - 床・箱・太陽の光・LightmapGI のシーンを、`--prepare` で焼けた。
    - 2つのメッシュに UV2 を付けた。
    - `level.lmbake` と `.exr` ができ、シーンに `add_uv2 = true` と lightmap のデータが保存された。
  - project.godot が1文字も変わらずに戻り、プラグインが消えた。
  - LightmapGI のないシーンでは、分かる誤りになり、そのときも project.godot が戻る。
- `uzu.py selftest all`: ok。

## 途中の失敗

- テストのビルドが2回失敗した: ClassDB のヘッダーを入れ忘れ、関数名を誤った（`class_has_method` ではなく `has_method`）。

## 注意

- 上流のドキュメントには「PrimitiveMesh は UV2 を持てないので焼けない」とあるが、今の PrimitiveMesh は add_uv2 で焼けた。上流の古い記述と思われる。上流のドキュメントは変えていない。
