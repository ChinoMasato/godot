# B-1001 サンプルゲーム『灯りの欠片』— 初回実エンジン検証（2026-11-18、リード）

## 結果
タイトル→村→欠片3つ収集→ランタン点火→クリアまで、実エンジンで最初から最後まで通った。
検証用コピーにドライバ（autoload）を足し、実入力（InputEventAction "interact"）と
プレイヤー移動（テレポート）で進行。最終状態 cleared=true / lantern_glow=1.0、スクリプトエラー0件。
スクリーンショット4枚: ai_loop/look_samples/hikari/（01_title / 02_village_day / 03_night / 04_clear）。

## 検証環境の正直な範囲
- この VM で自前ビルドした editor バイナリ（agent/hikari-muse 時点）＋ Xvfb ＋
  Compatibility レンダラー（ソフトウェア GL）。Forward+ のポストエフェクト
  （チルトシフト、ブルーム等）は Compatibility では効かないため、
  **HD-2D ルックの最終見た目は GPU 実機（ローカル）での確認が別途必要**。
  ゲームロジック・画面遷移・時刻変化・クリア判定はこの検証で確定。

## 捕まえたバグ（この検証の収穫）
main.gd が存在しない API `surface_material_override(0, mat)` を4箇所で呼んでおり、
最初の _box で _ready が中断 → プレイヤーが生成されずゲームが成立しなかった。
正しくは `set_surface_override_material`。修正はブランチ agent/hikari-muse の
bd50116 で ai-native へ統合済み。静的チェック（gdparse）では捕まらない型の誤りで、
実エンジンでの起動確認が必須であることの実例。

## 使った機能の対応（コード上の使用）
- HD-2D: UZULook.apply_hd2d（B-722 プリセット経由）＝ B-715〜B-722、B-725 の BlobShadow
  （NPC・プレイヤー・欠片）、B-716 Lit スプライト、B-718 きらめき粒子、B-720 葉の風揺れ素材
- U.ZU Picture: タイトル画面（B-901 ノード＋ title/picture.json、B-903 取り込み済みの深度・法線）
- テレメトリ: UZUTelemetry autoload（checkpoint "lantern_lit" 等、B-301 系）
- 入力は input_setup.gd でコード定義（エディタ GUI を使わない方針どおり）
