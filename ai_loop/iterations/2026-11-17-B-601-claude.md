# B-601 構造化フィードバックの形式定義 — claude (2026-11-17)

- ブランチ: ai-native に直接反映。
- BACKLOG B-601: 「詰まった場所／バグ／アイデア」を JSON スキーマとして定義し、AI バックログへ変換できることを小さなサンプルで示す。
  - 制約1: 感想は点数化しない（星評価を持たない）。
  - 制約2: 構造化するのは、作者と AI が直すための情報だけ。
  - 制約3: 感想の本文は「贈り物」としてそのまま作者に届ける。

## 内容（すべて ai_loop/feedback/）

- `FORMAT.md`: 形式と決まり。
  - 1件の項目:
    - 必須: v・kind（stuck／bug／idea）・message（プレイヤーの言葉）
    - 任意: where（scene／checkpoint／cell。cell は B-301 と同じ格子）・build・steps・expected・actual・signature（名乗り、任意）
  - 点数の項目（rating・stars・score など）を持たない。
  - プレイヤーの ID・連絡先は入れない。
- `to_backlog.py`（標準ライブラリだけ）: 変換ツール。
  - 検証: 点数の項目があれば受け付けない（大文字小文字を問わない）。知らない項目、種類の誤り、本文が空のものも受け付けない。
  - 変換: 同じ種類・同じ場所の感想を1つの課題にまとめ、BACKLOG の形式の行（`- [ ] F-001 [種類] 場所: 件数（感想 #番号）。判定: ...`）にする。
  - 判定の文: 種類ごとに決めた。
    - 詰まり: B-303／B-301 で、その場所の死亡・停滞が減ること。
    - 不具合: 手順で再現しなくなること。手順がなければ、まず確かめる。
    - アイデア: 作者が採否を決め、AI は承認まで実装しない。
  - 本文は課題に一切入れない。要約も言い換えもしない。`--gifts` で、本文をそのまま並べた作者向けのファイルを書く（名乗りがあれば添える）。
- `sample_feedback.json`: 5件のサンプル（詰まり2・不具合2・アイデア1）。

## 確認

- `to_backlog.py --self-test`: ok。
  - サンプル5件 → 課題4件（同じ場所の詰まり2件が1つにまとまる）。
  - 不具合で手順のあるものは、手順・期待・実際が判定に入る。手順のないものは「まず再現手順を確かめる」になる。
  - どの課題の行にも本文が含まれない。贈り物のファイルには本文がそのまま全部入り、名乗りも付く。
  - stars・Rating（大文字でも）・未知の種類・空の本文を受け付けない。
- 実行例（サンプルからの出力）:
  `- [ ] F-003 [詰まり] res://main.tscn cp2 付近: 2件（感想 #1, #2）。判定: 自己検証プレイ（B-303）とテレメトリ（B-301）で、この場所の死亡・停滞が減ること。`
- 全テスト: C++ の変更はないので、B-103 と同じバイナリで 1481/1481 pass。
- 途中の失敗: 同じ種類の中で「場所の指定なし」が先に並んだ。場所のあるものを先にするように直した。
