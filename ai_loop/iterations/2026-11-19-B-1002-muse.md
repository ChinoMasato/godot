# B-1002 自己検証と橋の実証（2026-11-19、Muse リード）

『灯りの欠片』を、AI プレイヤー（B-306）による閉ループ操作で完走し、機械判定した。
あわせて橋モックへの公開→感想取り込みを通した。検証スクリプトは
`ai_loop/samples/hikari/verify_playthrough.py`、レポートは
`ai_loop/samples/hikari/verify_report.json`。

## 自己検証プレイ（合格）

- 同じ種（7）で2回実行し、2回とも合格:
  - テレメトリのチェックポイントが順序どおり: start → shard_1 → shard_2 → shard_3 → lantern_lit
  - 最終状態（宣言状態 B-307）: shards=3、cleared=true
  - 開始時点の状態ハッシュが2回で一致（決定性の確認）: 1abc957f…（sha256 先頭8桁）
- 操作は観測（プレイヤー位置・欠片数）を見て進める閉ループ。経路は村の開けた
  レーンに沿うウェイポイント列（障害物の実効半径を避ける）。直進ステアリングは
  円形障害物に対して放射状に行き詰まるため、停滞検出＋接線迂回も併用。

## 検証が見つけた道具側の穴2件（B-310／B-311 として修正）

1. **B-310**: AI プレイヤーの press が `Input.action_press`（状態）だけで、
   `_unhandled_input`（イベント）で入力を読むゲームが一切反応しなかった
   （タイトルが始まらない）。control.gd で InputEventAction も送るよう修正。
   状態をポーリングするゲーム（B-306 サンプル等）への影響なし（self-test pass）。
2. **B-311**: aiplayer／selfplay はプロジェクトを `.godot` 抜きでコピーするため、
   インポート済み素材（フォント等）を preload するスクリプトが parse error で
   死んでいた（タイトル画面が無言で固まる）。コピー直後に1回インポートする
   よう修正（aiplayer.py と uzu.py selfplay の両方）。

## ゲーム側の整備（サンプルの作法として）

- 状態の宣言（B-307）: Main に `uzu_state()`（shards／cleared／プレイヤー位置）と
  グループ登録を追加。ハッシュで「同じ状態」を機械が言えるようにした。
- 移動とプレイ時間を `_process` から `_physics_process`（固定ステップ）へ移した。
  ロックステップ検証と決定性のため。見た目（カメラ・時刻・近接表示）は従来どおり。

## 橋の実証（合格）

- Web ビルドを橋モック（B-504）へ公開: game_id g_0001 / build_id b_0002 / status live。
  公開前チェック（B-502）が「エンジンの MIT ライセンスと第三者表示がない」を検出し、
  `prepublish.py add-notices` で ENGINE_LICENSE.txt / ENGINE_COPYRIGHT.txt を
  追加してから公開した（チェックが実際に効いた記録）。
- モックへ感想を1件投入（f_0003、B-601 形式、詰まり・池の欠片）し、
  感想取り込み（B-506）で課題ファイル（F-001、判定文つき）と
  「贈り物」ファイル（プレイヤーの言葉をそのまま）の両方が生成されることを確認。
