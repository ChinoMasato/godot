# B-205 UID チェック／修復 — claude (2026-11-18)

- ブランチ: ai-native に直接反映（リードの着手順。隙間作業）。
- BACKLOG B-205: .tscn／.tres と .uid の不整合（欠落・重複・参照切れ）を検査し、修復案を出す（適用は確認つき）。判定: 不整合を仕込んだサンプルで検出し、修復の後に B-203 が問題 0 件になること。

## 内容（エンジン本体の変更なし。uzu.py の Python。Windows でもそのまま動く）

- `uzu.py engine <project> uids [--fix]`（MCP の project_uids も同じ）。
  - 読むもの（テキストとして）:
    - シーン／リソースの見出しの uid
    - スクリプト・シェーダーの `.uid` ファイル
    - 素材の `.import` の uid
    - 参照（ext_resource）の uid とパス
  - 検出する不整合と、修復の案:

    | 種類 | 内容 | 修復の案 |
    |---|---|---|
    | `duplicate_uid` | 同じ UID のファイルが2つ以上（コピーで起きやすい） | 最初のものに残し、他に新しい UID を振る |
    | `missing_uid_file` | スクリプト・シェーダーに `.uid` がない | 参照が使っている UID があればそれで作り直す（参照を書き換えずに済む）。なければ新しい UID |
    | `orphan_uid_file` | 持ち主のファイルがない `.uid` | 消す |
    | `stale_uid` | 参照のパスは正しいが、UID が違う | パスの持ち主の UID にする（持ち主に UID がなければ UID を外す） |
    | `moved_path` | パスは切れているが、UID の持ち主はある（ファイルの移動） | 持ち主のパスにする |
    | `broken_reference` | パスも UID もたどれない | 自動では直さない（報告だけ） |

  - 既定では案を出すだけ。`--fix` で適用する（「適用は確認つき」）。
    - 適用は重複から行い、検査し直してから参照を直す。重複の UID を振り直すと、それを指す参照の判定が変わるため。
    - 適用の後にもう一度検査し、残った問題を返す。
  - 新しい UID は、エンジンと同じ方式（63 ビットの乱数を、34文字の表で文字にする）で作り、既存の UID と重ならないようにする。

## 確認

- 手で作った、エディタが書くのと同じ形（見出しと参照に uid がある）のプロジェクト:
  - そのままでは uids も validate も 0 件。
  - 仕込んだ不整合: シーンの複製（UID の重複）、`.uid` の削除、持ち主のいない `.uid`、参照の UID の改ざん、シーンの移動。
  - 結果: 6件を検出し、validate も参照切れを2件出した。`--fix` で6件を直すと、uids も validate（B-203）も 0 件になった（判定どおり）。消えた `main.gd.uid` は、参照が使っていた元の UID で作り直された。
- `uzu.py selftest engine` に5項目を足した: 検出の種類、validate が崩れを見つけること、修復で6件が直ること、UID が参照から戻ること、修復の後の validate が 0 件。tools も ok。
- 全テスト: C++ の変更はないので、B-308 と同じバイナリで 1496/1496 pass。

## 途中で分かったこと

- エンジンを `--script` で動かして保存したシーンには、uid が付かなかった（エディタで保存したときだけ付く）。そのため、検査の試験用のプロジェクトは、エディタの形を手で書いて作った。
- 最初の版では、`.uid` が消えたスクリプトへの参照を「古い UID」として「UID を外す」案にしていた。参照が使っている UID で `.uid` を作り直すほうが、何も書き換えずに済むので、そう直した。
