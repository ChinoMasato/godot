# B-801 Windows で AI ツールを動かす（ai_loop/uzu.py） — claude (2026-11-17)

- ブランチ: ai-native に直接反映（Q10 の承認による）。
- BACKLOG B-801: bash で書いていた AI 用のツールを、OS を問わず動く Python に移す。

## 内容

- `ai_loop/uzu.py`（新規、標準ライブラリだけ）: 入口を1つにした。
  - `engine`: run・check・validate・shot と、engine_tool.gd の全コマンド
  - `look`: shot・check・panorama と、look_tool.gd の全コマンド
  - `selfplay`
  - `publish`
  - `selftest [engine|selfplay|tools|all]`
- エンジンのバイナリ: 環境変数 `GODOT` があればそれを、なければ `bin/` から OS に合うエディター版を探す。Windows では `.console.exe` を優先する（標準入出力を保つため）。
- 描画（shot・panorama・録画・AI プレイヤーの画面）:
  - Linux でディスプレイがないとき: これまでどおりソフトウェア Vulkan と仮想ディスプレイ。
  - それ以外（Windows・Mac・ディスプレイのある Linux）: 実際の GPU を使う。
  - `UZU_SOFTWARE_RENDER=1` で、ソフトウェア描画を強制できる。
- 薄い包みにしたもの（中身は `uzu.py` を呼ぶだけ。使い方は変わらない）: engine.sh・look.sh・selfplay.sh・screenshot.sh・publish.sh・engine_selftest.sh・selfplay_selftest.sh
- 置き換えたもの:
  - engine_selftest.sh と selfplay_selftest.sh の中身: 同じ検査を Python に移し、Windows でも走るようにした。
  - MCP サーバー: `uzu.py` を、今動いている Python で直接呼ぶ。
  - aiplayer.py・bench.py・bridge/client.py: バイナリの探索と描画の準備を `uzu.py` に任せる。Linux のパスの決め打ちをなくした。
- Windows 用:
  - `ai_loop/windows/uzu.cmd`: `py -3` で uzu.py を呼ぶ。
  - README に使い方を書いた。
  - 出力は UTF-8 に固定した（Windows のコンソールの既定の文字コードで、日本語が化けないように）。
- Linux 専用のまま: ビルドのロックと計測（build_locked.sh・measure.sh・agent_*.sh）。Windows のビルドは setup.ps1 が受け持つ。

## 確認（Linux）

- `uzu.py selftest all`: ok（約15秒）。
  - engine: 25項目。以前の engine_selftest.sh の全項目と look info。
  - selfplay: 再現性と、乱数の種。
  - tools: mcp_server・bench・prepublish・aiplayer・telemetry report・feedback・bridge mock・bridge client の8つ。
- 包みの経由でも ok: engine_selftest.sh、selfplay_selftest.sh。
- 描画を使う機能: look.sh shot（仮想ディスプレイで描画）、screenshot.sh、look check、panorama（256×128）、AI プレイヤーの画面（render=True）。どれも以前と同じ結果になった。
- 誤りの扱い: プロジェクトでないフォルダーは、分かる誤り（終了コード 2）になる。publish.sh でつながらない先は ok: false になる。
- 全テスト: C++ の変更はないので、B-103 と同じバイナリで 1481/1481 pass。

## 途中の失敗
