# B-1108 オーディオスプライト（Muse lead branch、2026-11-19）

複数の SE を1つの音声ファイルに詰め、区間指定で再生する仕組み。新クラスは作らず
`UZUSfx`（B-1105）の拡張として実装した。ブランチ `agent/b-1108-lead`、統合はリード。

## 実装

### C++（scene/resources/uzu_sfx.{h,cpp}、doc/classes/UZUSfx.xml）

- 純粋な区間値 `UZUSfxSpriteSegment`（start/length サンプル数と秒、end、contains、
  should_stop）をヘッダに追加。UZUJuice の状態構造体と同じ流儀で、AudioServer や
  シーンツリーなしで単体テストできる。
- 追加した静的 API（すべて ClassDB 登録済み）:
  - `sprite_manifest(names, gap_ms = 50, seed = 0)` → 名前 → {start_sample,
    length_samples, end_sample, start_sec, duration_sec, end_sec} の Dictionary。
    プリセットのパラメータだけからの純粋計算（AudioServer 不要）。
  - `generate_sprite(names, gap_ms = 50, seed = 0)` → 連結した単一の
    AudioStreamWAV（16bit モノラル）。各 SE の間に gap_ms の無音を挟む
    （先頭・末尾には入れない）。
  - `build_sprite(...)` → {stream, manifest, sample_rate, gap_ms, gap_samples,
    total_samples, total_sec} を1コールで返す（エージェント／CLI 向け）。
  - `get_sprite_segment(manifest, name)`、`sprite_should_stop(pos_sec, segment)`
    （区間終了の純粋な停止条件）。
  - `play_sprite(parent, sprite, manifest, name, volume_db = 0)` → 区間だけを
    再生する AudioStreamPlayer。開始位置は区間の start_sec、終了は自動生成
    ランタイムノード `UZUSfxSpriteRuntime`（UZUJuiceRuntime と同じ方式）が
    再生位置を監視して stop＋queue_free する。区間はプレイヤーの
    メタデータ `uzu_sprite_segment` に保持。ツリー外では再生を開始せず、
    ツリーに入った時点でランタイムが開始する（`play()` はツリー外では
    エラーになるための対策）。
- 生成とマニフェストは同じ区間計算（`sprite_layout`）から出すのでずれ得ない:
  区間のサンプル数は generate() と同じ `int((attack+sustain+decay) * rate)`。
  生成側でも実ストリームの長さがレイアウトと一致することを確認してから詰める。
  同じ名前が重なったらマニフェストは最初の区間を保持する。
- 決定的: 同じ names／gap／seed からは同じサンプル列とマニフェストになる
  （乱数は UZUSfx の既存流儀どおりプリセットの seed に従う）。

### CLI（ai_loop/engine_tool.gd、uzu.py、mcp_server.py）

- `engine sfx-sprite --out res://sfx/sprite.wav [--names hit,jump,pickup,coin]
  [--gap-ms 50] [--seed 0] [--manifest-out res://sfx/sprite.json]`:
  スプライトを1本の WAV ファイル（`AudioStreamWAV.save_to_wav`）に保存し、
  マニフェストを JSON で隣に書く。「1ファイル」の実物はこの WAV。
  結果 JSON には segments と合計、describe（長さ・ピーク等）も返す。
- MCP に `sfx_sprite` を追加。uzu.py の engine selftest に sfx-sprite の
  検証（生成・マニフェスト JSON の一致・未知プリセットのエラー）を追加。

## 検証

- ビルド: `scons platform=linuxbsd target=editor tests=yes -j2`（flock 経由）
  成功。フルビルド 2h17m（うち他エージェントのビルド待ちを含む実時間は別）。
- 新規テスト（tests/scene/test_uzu_sfx.cpp に3件追加）:
  - マニフェストの純粋計算が生成 SE の実長とサンプル単位で一致、gap 0／200ms の
    ずれ、seed の決定性、未知名・空リストのエラー。
  - スプライトの各区間のバイト列が単体プリセットと完全一致、区間の間の
    ギャップが完全な無音、合計＝最後の区間の end、2回の生成がバイト一致、
    別 seed で変化。
  - play_sprite の設定（ストリーム・メタデータ・音量）と停止条件
    （sprite_should_stop と UZUSfxSpriteSegment の contains／should_stop）。
  - UZUSfx 全体: 8ケース／344 assertion 全 pass。
- 全テスト: 1561ケース中 1559 pass／2 fail／3 skip。fail 2件は
  [UDPServer]（tests/core/io/test_udp_server.cpp）で、サンドボックス UDP の
  環境起因の既知失敗（B-1304 等でも同一。失敗 assertion 29件はすべてこの2件内）。
- CLI 実地（最終バイナリ）:
  `uzu.py engine <proj> sfx-sprite --names hit,jump,pickup,coin --gap-ms 50
  --out res://sfx/sprite.wav` → ok、sprite.wav 100,590バイト（44バイトヘッダ＋
  50,273サンプル×2）、sprite.json 生成。WAV を読み戻して確認: モノラル
  44100Hz、50,273フレーム、hit と jump の間のギャップ2,205サンプルは全て0、
  coin の end_sample = 総フレーム数。未知プリセットはエラーで正しく失敗。
- `uzu.py selftest engine` 全 ok（sfx-sprite／sfx-sprite unknown preset を含む）、
  `selftest tools` も ok。

## 途中で見つけて直したもの

1. ギャップが無音にならない＋生成が決定的でない: `Vector<uint8_t>::resize` は
   POD をゼロ初期化しないため、ギャップに未初期化メモリが残っていた。
   `memset` で明示的にゼロ埋めして解消（テストが両方の症状を捕まえた）。
2. ツリー外の `AudioStreamPlayer::play()` は「Playback can only happen when a
   node is inside the scene tree」エラーになる。当初の「常時 play する」方式を
   やめ、開始はツリー内でのみ行い、ツリー外のプレイヤーはランタイムが
   入ツリー時に開始する方式にした。
3. Godot 4.8 の `Vector::operator[]` は読み取り専用参照を返す。レジストリの
   更新は要素のコピー＋`ptrw()` 経由にした（コンパイルエラーで検出）。
