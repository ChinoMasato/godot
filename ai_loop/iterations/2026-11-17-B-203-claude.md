# B-203 プロジェクト検証コマンド（engine.sh validate） — claude (2026-11-17)

- ブランチ: ai-native に直接反映。
- BACKLOG B-203: プロジェクト全体の読み込みとスクリプト検査を一括で行い、問題一覧を JSON で返す。

## 方針

- エンジン本体に新しいコマンドラインオプション（仮称 `--validate-project`）は足さず、エージェント用ツール（`ai_loop/engine.sh` と `engine_tool.gd`）のコマンドにした。理由: 中身はすべて公開 API（ResourceLoader、ProjectSettings、Script）で書けるので、エンジンの公開 API の形を変えずに済む。コマンド名は `validate`。
- スクリプトのエラーの詳細は、B-202 の `--check-only --json` を使って足す。

## 内容

- `engine_tool.gd validate`: res:// 以下（.godot などの隠しフォルダーは除く）を全部見る。
  - シーン／リソース（.tscn .scn .tres .res）:
    - 依存先が存在するかを調べる（UID でもパスでも）→ `missing_dependency`（`target` に依存先）
    - 読み込めるかを調べる → `load_failed`
  - スクリプト（.gd）: 読み込んで、正しいかを調べる → `script_error`。abstract クラスは実体を作れないが正しいので、問題にしない。
  - project.godot:
    - メインシーンがあるか → `missing_main_scene`
    - autoload の参照先があるか → `missing_autoload`
  - 結果: `{"ok", "command": "validate", "checked", "issues": [{"kind", "file", "target"?, "message", "errors"?}]}`
- `engine.sh validate`: 上を実行したあと、`script_error` ごとに `--check-only --json` を走らせ、`errors`（行・列・code・メッセージ）を付ける。問題が1件でもあれば終了コード 1。
- MCP に `project_validate` を追加した（ツールは25個になった）。

## 確認

- 参照切れを含むテスト用プロジェクト:
  - 構成: 存在しない画像を参照するシーン、未定義の名前を使うスクリプト、存在しないファイルを指す autoload。
  - 結果: 3件とも検出した。スクリプトのエラーには行3・列8と code が付いた。
- 直したプロジェクト（abstract クラスと Resource スクリプトを含む）: 問題0件、ok。
- メインシーンだけ消したとき: `missing_main_scene` が1件。
- `engine_selftest.sh` に2項目を追加した。
  - validate broken: 壊れたスクリプトと参照切れのリソースを検出し、エラーの行が正しい。
  - validate clean: 直すと0件になる。
  - 全項目 ok。`mcp_server.py --self-test`: ok。
- 全テスト: C++ の変更はないので、B-202 と同じバイナリで 1481/1481 pass。

## 途中の失敗

- 最初は `Script.reload()` で正しさを調べたが、正しい autoload スクリプトが「Already in use」で失敗した。読み込み済みのものは reload できないため。`can_instantiate()`（abstract なら `is_abstract()`）で調べるように直した。
- self-test の期待を「問題がこの2件ちょうど」にしたら fail した。参照切れのリソースは `load_failed` も出るので（これも正しい検出）、「この2件を含む」に直した。
