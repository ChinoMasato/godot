# B-104 ベンチマークの合否判定（ai_loop/bench.py） — claude (2026-11-17)

- ブランチ: ai-native に直接反映。
- BACKLOG B-104: `--benchmark-file` の計測結果をベースライン JSON と比べ、閾値を超えて悪化した項目があれば非0で終了する（計測ラッパーでも可）。

## 内容

- `ai_loop/bench.py`（新規、標準ライブラリだけ）:
  - `run --project P [--out base.json] [--repeat 3] [--frames 60]`: エンジンの `--benchmark --benchmark-file` でプロジェクトをヘッドレス実行する。repeat 回分の各計測項目の中央値をとる。`--out` を付けるとベースラインになる。
  - `compare --baseline B --current C`: 2つの結果を比べる。
  - `check --project P --baseline B`: run と compare を続けて行う。
  - 悪化の判定: 次の2つを両方満たすと「悪化」。満たさなければ ok。
    1. 現在値 > ベースライン ×（1＋閾値。既定は 0.25）
    2. 差が `--min-ms`（既定は 5 ms）を超える
  - 2 があるので、マイクロ秒単位の小さい項目が揺れで fail することはない。
  - 出力: 1行の JSON `{"ok", "regressions", "improvements", "missing", "new"}`。悪化があれば終了コード 1。
  - エンジンが出した生の `--benchmark-file` も、そのままベースラインとして読める。

## 確認

- `bench.py --self-test`:
  - 何も変えずに2回計測すると pass する。
  - 起動時に 300 ms 待つ autoload を足した（人為的に遅くした変更）と、fail になり、`[Startup] Load Autoloads` が悪化として出る。
  - compare 単体: 揺れの範囲は pass、2倍は fail。消えた項目は missing として出る。
  - 3回続けて実行して、3回とも ok（各2〜3秒）。
- 手で試した: テスト用プロジェクトで baseline を作り、check すると ok（終了コード 0）。終了処理が速くなった項目は improvements に出た。
- 全テスト: C++ の変更はないので、B-202 と同じバイナリで 1481/1481 pass。
- 途中の失敗: self-test のプロジェクトにメインシーンがなかったので、エンジンが計測ファイルを書かずに終了した。メインシーンを足して、エラーメッセージにもその旨を書いた。

## 申し送り

- 今ある計測項目は起動・終了の区間だけ。フレーム時間（描画の重さ）はまだ測っていない。ルック（B-7xx）の重さを見るなら、フレーム時間の計測項目を足す課題が要る。
