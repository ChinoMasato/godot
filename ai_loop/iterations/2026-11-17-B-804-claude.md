# B-804 書き出しの設定とテンプレート — claude (2026-11-17)

- ブランチ: ai-native に直接反映（Q10 の承認による）。
- BACKLOG B-804: export_presets.cfg をコマンドで作り、テンプレートの有無を調べ、実際に書き出して prepublish → 公開（モック）まで通す。

## 内容（エンジン本体の変更なし）

- `engine_tool.gd`:
  - `export-preset --platform web|linux|windows|macos|android [--name] [--out] [--template zip]`: export_presets.cfg を作る、または同じ名前のプリセットを更新する。
    - エンジンの ConfigFile で書くので、形式はエディタと同じ。
    - エディタが読むのに必須の項目（include_filter／exclude_filter）も書く。exclude は `build/*`（書き出し先を含めないため）。
    - Web では、スレッドなし（特別なサーバーの設定なしで、どこでも動く）と、拡張なしを既定にした。
    - `--template` は、プリセットのカスタムテンプレート（custom_template/release と debug）に入れる。テンプレートの置き場（バージョンごとのフォルダー）を使わずに済むので、Windows でも同じ手順になる。
  - `presets`: プリセットの一覧。
- `uzu.py engine`:
  - `export --preset <名前> [--out] [--debug]`: 書き出して、できたファイル・合計サイズ・構造化エラーを返す。テンプレートがなければ、そう案内する（hint）。
  - `templates`: エンジンの版、テンプレートの置き場とそこにあるもの、各プリセットのカスタムテンプレートが実在するか。
- `bridge/client.py publish --add-notices yes`: 書き出しの後に、エンジンのライセンスと第三者の表記を入れる（B-502 の add-notices）。
- MCP に4つ足した: export_preset、export_presets、export_templates、project_export。
- **Web 用テンプレートのビルド**（このフォークのもの。UZULook などの独自のクラスを含むので、上流の公式テンプレートでは代わりにならない）:
  - Emscripten 7.0.0 を emsdk で入れた（一時フォルダー。環境には残らない）。
  - `scons platform=web target=template_release threads=no -j4` で約1時間。
  - できたもの: `bin/godot.web.template_release.wasm32.nothreads.zip`（9.3 MB）。bin/ は git に入れない。

## 確認

- 実際の書き出し: サンプルゲームを Web に書き出した（9ファイル、30 MB、エラーなし）。
- ブラウザで動くこと: 組み込みの Chromium で開き、「U.ZU Engine v4.8.beta」の起動表示と、ゲームの画面（線と穴）を確かめた。
- 公開まで（別プロセスのモック）:
  - `publish.sh <プロジェクト> --preset Web`: ライセンスと表記がないので、公開前チェックで止まり、何も送らない。
  - `--add-notices yes` を付けると、live になり、遊べる URL が返る（終了コード 0）。
  - プロジェクトには `.uzu_publish.json` に game_id だけが残る。
- `uzu.py selftest all`: ok。engine に6項目を足した。
  - プリセットの作成・追加・同じ名前での更新、誤ったプラットフォーム。
  - templates でのカスタムテンプレートの有無。
  - ないプリセットでの書き出しが、プリセットの一覧付きの誤りになること。
- 全テスト: 1485/1485 pass（B-805 と同じビルド）。

## 途中の失敗

- 最初のプリセットでは include_filter／exclude_filter がなく、エディタが読めずに書き出せなかった。足して直した。
- self-test の補助関数が、誤りに付けた追加の情報（プリセットの一覧）を落としていた。直した。

## 追記: テンプレートの共有（オーナー「確認したいところは承認前提で良い」、2026-11-18）

- 置き場: リポジトリの `export-templates` ブランチ。
  - ai-native と履歴を共有しないブランチ（orphan）なので、9 MB のバイナリが本線の履歴に入らない。
  - 置いたもの: `web/` に zip と info.json（sha256、エンジンのコミット 1300d7ad8、Emscripten 7.0.0、ビルドの手順）。
- `uzu.py engine <project> templates --fetch`: このブランチから `bin/templates/` に取り出す（sha256 を確かめる）。
- `export-preset --template auto`: 取り出したテンプレートを使う。なければ取り出しから行う。
- 確認: bin/templates を消した状態から、取り出し → プリセット → 書き出しまで通った。
- エンジンを変えて、ゲームが新しい機能を使うようになったら、テンプレートを作り直して差し替える（README に書いた）。
