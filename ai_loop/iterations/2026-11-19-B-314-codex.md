# B-314 リプレイログの照合 — Codex

`uzu.py replay-compare` と MCP の `replay_compare` を追加した。Godot の起動を必要とせず、既存の selfplay 出力や別途取得した JSON／JSONL ログを比較できる。

```sh
python3 ai_loop/uzu.py replay-compare --expected baseline.jsonl --actual replay.jsonl
python3 ai_loop/uzu.py replay-compare --expected checkpoints.json --actual replay.jsonl --snapshots
```

- 既定では順序を保って全項目を比較する。JSON のキー順は比較に影響しない。最初の不一致についてレコード番号（1始まり）、レコードにある `frame`／`time`、JSON Pointer、期待値と実値を返す。欠落・余分な項目は、存在する側の値と理由を返す。
- `--snapshots` は期待した項目だけを照合する。ログを順に調べ、`frame` または `time` と、期待側にあれば `type`／`kind` でイベントを選ぶ。状態の一部を検証でき、同じログ行を複数の期待に使わない。たとえば `{"frame":50,"type":"checkpoint","id":"cp1"}` を期待にできる。
- MCP の引数は `expected`、`actual`、任意の真偽値 `snapshots`。ファイルの絶対パスを指定できる。CLI は一致0、不一致1、入力エラー2を返す。空・不正な入力は成功扱いしない。
- JSON は空でないオブジェクトまたは配列、JSONL は1行1オブジェクト。全項目比較ではセッションIDなどの違いも検出する。状態だけを判定する場合は期待スナップショットに比較したい項目を指定する。
