# B-1221 イメージ先行フロー（2026-11-20、Muse / lead branch）

仕様イラスト1枚から、歩けるシーン雛形を B-1207 の宣言的 spec として起こす道具を実装した。

## 実装

- **`ai_loop/image_scene.py`（新規、標準ライブラリのみ）**: 解析の中核。純関数 `analyze(image, depth=None) -> (spec, report, assets)`。
  - 深度プロキシ: `--depth` で外部推定マップ（B-903 の取り込み経路）を渡せばそれを使い `basis: observed`。無ければヒューリスティック（縦位置が支配的＋局所ディテールで手前に寄せる）で `basis: inferred` と明示。
  - レイヤー分離: 深度を3帯（背景／中景／前景）に分け、帯の中で色トレラントな flood fill（実行平均との距離 0.13）で要素を切り出す。帯境界で割れた同一物体は、ほぼ同色（0.05）・接触・横重なり条件でマージ。
  - 床の分類: 下端に達する領域、地色と同色の領域、床領域とほぼ同色（0.03）の領域はカードにせず床として記録（`layers.skipped` に理由つき）。物体色は床色に 0.05 以内で近づくことがあるため、色一致の閾は意図的に厳しくした（物体を失う方が、道の板が残るより悪い）。
  - 候補抽出: 明るい塊→ `glow` 候補、地に立つ縦長形状（アスペクト 1.6〜3.4）→ `door` 候補。どちらも `basis: inferred`＋理由＋信頼度つきで、確定扱いしない（B-1509 の流儀）。地に立つ幅 0.7m〜背景幅40% のカードは当たり判定候補として `collision: true`。
  - レイアウト: 背景カードは全面の1枚絵。カメラは背景が画角いっぱいに収まる位置に置き（fov 既定50°）、カードの3D位置・大きさはそのカメラを通した透視投影で決める。基準カメラは spec の `camera` に入り、B-1223 がここから差分を取る。地面の色はイラスト下端の平均色（observed）。
- **`ai_loop/build_tool.gd`（拡張）**: spec に `cards`（テクスチャ付き板ポリ。alpha scissor、両面、既定 unshaded、`collision` で薄い StaticBody）と `markers`（`uzu_candidate` メタデータ付き Area3D）を追加。`ground` に `position` と `collision`（上面がちょうど y=0 の床ボディ）を追加。B-1216 の板ポリ表現はこの cards が担う。
- **`uzu.py image-scene <project> --image ... [--depth ...] [--out ...] [--shot ...] [--no-build] [--no-walk]`**: 資材（レイヤーPNG）と spec.json／report.json／walk_targets.json をプロジェクト内に書き、インポート→構築→歩行確認までを1コールで行う。
- **`ai_loop/selfplay/image_walk.gd`（新規）**: ナビメッシュなしの雛形用歩行確認。カプセルが物理でウェイポイントを直進し、到達／詰まり／落下を JSON で返す。
- **見本**: `ai_loop/samples/image_scene/`。イラストは `make_illustration.py` が手続き的に描いた夕景の村（960×540、標準ライブラリのみ。出所はこれ。AI生成画像ではないが、フローは任意のPNGを同じに扱う）。生成物（spec／report／tscn）も同梱。
- テスト: `ai_loop/tests/test_image_scene.py`（合成イラストで spec 形状・候補の inferred・深度マップ observed・床分類を固定。selftest tools に登録）。`ai_loop/image_scene_check.py` が見本の生成→歩行→spec編集→再構築を通しで確認する。

- 歩行: ウェイポイント 5/5 到達、落下なし。

## 限界・できなかったこと

- 入力は PNG のみ（8bit RGB/RGBA、非インターレース。標準ライブラリ制約。JPEG は image_diff と同じく非対応）。
- ヒューリスティック深度は縦位置が支配的なので、帯はほぼ水平に割れる。空中に浮く要素（鳥・垂れ幕）や、手前にあるのに上部に描かれた要素の奥行きは外す。実モデル（Depth Anything 等）の深度マップを渡す経路が本命で、合成マップでの observed 経路のみ確認済み。
- 色の近い物体と地面は分離できない（家の壁と影の地面が flood fill でつながり、地面ごとカードになることがある）。カードは二重像（背景にも同じ家が描かれている）になる——『黄昏六号館』の作りと同じ割り切り。
- 扉候補には誤検出がある（見本ではランタンの柱が door_1 になった）。候補は候補として AI／人間が選別する前提。
- 下端でフレームに切れた前景物体は床として失われる（skipped の理由に明記）。
- 差分数値による合否（B-1223）と仕様画像の登録管理（B-1222）は範囲外。本項目からは基準カメラを spec に渡すところまで。
