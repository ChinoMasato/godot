# ローカル GPU の「デバイス喪失」の切り分け — Claude Code ローカル（2026-11-18）

Codex の B-720 GPU 記録（agent/b-720-codex-gpu）で、Vulkan のデバイス喪失（fence wait error -4、最後の目印 `BLIT_PASS`、続いて `nvoglv64.dll` のアクセス違反、終了コード 3221225477）が 2 回出て、GPU 確認の一部が見送りになった。原因がエンジンにあるかを、読むだけの調査で切り分けた（再現のための負荷試験はしていない。理由は下記）。

## 結論: エンジンの不具合ではなく、このPC（RTX 4050 Laptop、NVIDIA 617.42）の GPU の不安定さ

- Windows のシステムログ（直近 2 日）に、NVIDIA ドライバーのイベントが 102 件ある。
  - イベント 13（`Graphics Exception: ESR ...`。シェーダー実行中の例外、いわゆる Xid 13）が 53 件。
  - イベント 153（GPU のリセット）が 49 件。
- 起きた時刻は次のとおり。
  - Godot の作業中: 11/17 の複数回、11/18 07:38（Claude Code の HD-2D 撮影で 1 回だけ描画に失敗した時刻と一致）、11/18 14:41〜14:43（Codex の B-720 の 2 回の失敗と一致）。
  - **Godot と関係ない時刻にも出ている**: 11/16 19:24（このフォークの作業を始める前）、11/18 10:31〜10:33（ブラウザーでの動画再生中）。
- このPCでは、GPU のスケジューラーが原因のブルースクリーン（bugcheck 0x119、`DRIVER_FAILED_SUBMIT_COMMAND`）が、9 月から繰り返し記録されている。ドライバーを 617.42 に更新した後も再発している（Codex の別調査）。
- アプリの異常終了の記録は 3 件とも `godot.windows.editor.x86_64.exe` の `nvoglv64.dll`（NVIDIA の Vulkan ドライバー本体）で、同じ位置で落ちている。これは GPU のリセット後にドライバー内で落ちたもので、エンジンのコードの位置ではない。
- 以上から、Godot のデバイス喪失は、PC 全体で起きている GPU の障害がたまたま Godot の実行中に当たったもの、と判断する。B-719／B-720 の機能の不具合を示す証拠ではない。

## 負荷試験をしなかった理由

このPCでは GPU の障害がブルースクリーン（PC 全体の停止）まで進むことがあるため、再現させるための連続実行はしない。ドライバー（メーカー推奨版との比較）やハードウェアの診断は、PC の持ち主の判断に任せる。

## 道具の変更

- `ai_loop/look_samples/shadow_grain.py` と `ai_loop/windows/hd2d_gpu.py`: 描画に失敗したら **1 回だけ**やり直す。最初の失敗は結果の `retried` に残す（不安定さを隠さないため）。2 回続けて失敗したら、今までどおり失敗として返す。
- Codex の `effects_gpu.py` は「最初の失敗で止める」設計なので変えていない。

## ローカルで GPU の結果を読むときの目安

- 1 回だけの描画失敗やデバイス喪失は、まず PC の障害を疑う（Windows のシステムログで nvlddmkm のイベント 13／153 の時刻を見る）。
- 同じ場面で 2 回続けて落ちる、または特定の効果を入れたときだけ落ちるなら、エンジン側を疑って調べる。
