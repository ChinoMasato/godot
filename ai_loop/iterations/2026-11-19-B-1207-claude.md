  - 判定: 短い仕様から村シーンが組み上がり、B-1204 のレポートが一緒に返ること。

## 内容

- **`ai_loop/build_tool.gd`**（新規。headless の SceneTree スクリプト）: 1つの JSON 仕様から、シーンを組み立てて保存する。
  - 仕様のキー:
    - `scene`（保存先）、`main`（メインシーンにする）
    - `look`（quality／atmosphere／clouds／rig）
    - `ground`（大きさ、色か素材）
    - `camera`（位置、注視点、レンズか fov）
    - `models`（プリミティブ名か res:// のメッシュ／シーン／GLB。位置、y 回転、大きさ、色か素材）
    - `scatter`（B-1203。`on` で面を指定し、除外・間隔・傾きなども指定できる）
    - `lamps`、`particles`、`water`（B-727）、`godrays`
  - 素材は3通りで指定できる: 色、ルックの素材の種類（foliage／skin など。色の上書きもできる）、res:// の素材。
  - 中では UZULook（apply_to_scene、add_lighting_rig、add_lamp、create_particles、add_water、add_god_rays）と、UZUScatter を呼ぶ。新しいエンジン機能は使っていない。
  - 散布用のプリミティブは、既定でローポリにした（球 12×6）。B-1204 の測定で、既定の球（4,224 三角形）は小物には重すぎると分かったため。
  - **仕様の誤りは、まとめて返す**: 知らないキー（使えるキーの一覧付き）、型の誤り、存在しない面の名前、知らない atmosphere／lens／particles の種類。
    - 返し方: `{"ok": false, "problems": ["models[0]: unknown key 'colour' (allowed: ...)", "scatter[0].on: no MeshInstance3D 'Lawn' ...", ...]}`。
    - 誤りがあるときは、何も保存しない。
- **`uzu.py build <project> --spec spec.json [--shot out.png] [--budget JSON | --budget-file] [--no-render] [--no-report]`**:
  - 組み立てたあと、その結果のリッチ度レポート（B-1204: 要約、実際のフレーム、予算の合否、ヒント、重いノード）を一緒に返す。
  - `--shot` で、その場で撮影もする（`screenshot()` が、メインでないシーンも撮れるようにした）。
  - MCP: scene_build。MCP サーバーは、コマンド名のない道具（`uzu.py build`）も呼べるようにした。
- **仕様の例**: `ai_loop/look_samples/specs/village.json`（4.6 KB）。
  - 中身: 夕方の村。草地 60 m 四方、道、家5軒（壁と屋根）、木6本、井戸、灯り3つ、蛍。
  - 散布: 草（密度 3）、花（0.6）、石（0.25、間隔 0.8 m）。家・道・井戸のまわりは除外した。
