# B-802 リソース・プロジェクト設定・入力の割り当て・取り込みの操作 — claude (2026-11-17)

- ブランチ: ai-native に直接反映（Q10 の承認による）。
- BACKLOG B-802: エディタなしでは触れなかった、ノード以外のものを AI から操作できるようにする。

## 内容（エンジン本体の変更なし）

- `engine_tool.gd` に追加したコマンド（`uzu.py engine <project> ...`、`engine.sh` でも使える）:
  - **リソースファイル（.tres／.res）:** `res-new`（クラスと初期値を指定して作る）・`res-props`・`res-get`・`res-set`
    - 値の書き方はノードの set と同じ（Godot のテキスト形式。res:// パスは読み込み、クラス名は新しく作る）。
  - **プロジェクト設定:** `setting-get`・`setting-set`。エンジン自身の保存（ProjectSettings.save）で project.godot に書くので、形式は互換のまま。
  - **入力の割り当て:** `action-add`（キー名・マウスボタン・ゲームパッドのボタン。既定は追加、`--replace` で置き換え）・`action-remove`。
    - 装置は「すべて」（-1）にした。エディタで割り当てたときと同じ。
    - キー名を誤ると、名前の例付きの誤りになる。
  - **取り込みの設定:** `import-get`・`import-set`（その素材の .import の params を読み書きする）。
- `uzu.py engine <project> import`: エンジンの `--import` で素材を取り込む（取り込み直しも同じ）。
  - 取り込んだ素材の一覧と、構造化エラー（B-201）を返す。
  - `import-set` の後は、自動で取り込み直す。
- MCP に11個のツールを足した（37個）: resource_new／props／get／set、setting_get／set、action_add／remove、assets_import、import_get／set。

## 確認

- `uzu.py selftest all`: ok。engine の self-test に、この項目の検査を12個足した。
  - リソースを作って値を設定し、読み直すと値が合う。
  - ないプロパティや、リソースでないクラスは誤りになる。
  - 設定を変えても、既存の設定（main_scene）が消えない。
  - アクションの追加（キーとマウス）と削除。誤ったキー名は誤りになる。
  - PNG を取り込み、圧縮の設定を変えると、取り込み直した後の設定が 2 になる。
  - ないパラメーターは誤りになる。
- 手で試した: 圧縮の設定を 2（VRAM 圧縮）にすると、実際に `.s3tc.ctex` が作られた（取り込み直しが起きた）。
- 全テスト: C++ の変更はないので、B-103 と同じバイナリで 1481/1481 pass。

## 注意

- `setting-set`／`action-*` で保存すると、エンジンが `config/features`（版の印）を project.godot に足すことがある。エディタで保存したときと同じ振る舞い。

## 途中の失敗

- 最初の版では、キーの割り当ての装置が 16、ゲームパッドが 0（1台目だけ）になっていた。エディタと同じ -1（すべて）に直した。
