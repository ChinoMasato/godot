# B-403 機能カタログとエージェントの自己発見（Muse (lead branch)、agent/b-403-lead）

## 実装

エージェントが「何ができるか」をドキュメント全読みせずに発見できるよう、
道具の定義そのものから生成する機械可読カタログを実装した。手書きの
二重管理は持たない。

- **生成器 `ai_loop/make_catalog.py`**: 次の定義から抽出して
  `ai_loop/catalog.json` を生成する。`--check` で、コミット済み
  カタログと新鮮な抽出のエントリ集合が食い違えば fail する。
  - `cli`（12件）: uzu.py の main() のディスパッチ（AST）を正とし、
    説明と usage はモジュール docstring から。
  - `command`（69件）: uzu.py engine/look/map のサブコマンド。
    uzu.py 内で処理するものは engine()/look() の AST から、
    GDScript 側は engine_tool.gd / look_tool.gd / map_tool.gd の
    `match command:` のアーム、`command ==` 比較、info の commands
    リスト、ヘッダコメントの説明から。説明の fallback は MCP 表。
  - `mcp`（70件）: mcp_server.py の TOOLS 表そのまま。
  - `preset`（6件）: ai_loop/presets/ 配下の JSON の `_about`。
  - `script`（22件）: ai_loop/*.py（docstring）と *.gd（冒頭 ##）。
  - `class`（14件）: doc/classes/UZU*.xml と
    modules/*/doc_classes/UZU*.xml の brief_description。
  - 合計 **193件**。各エントリは名前・説明・タグ・実装場所（source）
    つき。コマンドには usage、MCP には maps_to（対応する CLI）も付く。
- **検索 `ai_loop/catalog.py`**: `uzu.py catalog <単語>... [--limit N]`。
  名前・説明・タグへの部分一致（複数語は AND、大文字小文字無視）。
  結果は従来どおり1行 JSON（`{"ok": true, "query", "count", "matches"}`）。
  ヒット0件も ok（「存在しない道具は載っていない」ことの確認に使える）。
- **MCP `catalog_search`**: mcp_server.py の TOOLS に追加し、
  call_tool で uzu.py catalog へ中継。self-test にも確認を追加
  （"sfx" で sfx_make がヒット、造語では0件）したので、CI の
  `uzu.py selftest all` で毎回検証される。

## 開発中に見つけた抽出の落とし穴（記録）

- GDScript の辞書リテラル（PBR プリセット名 "wood" 等）が match
  アームと誤検出された → アーム抽出を `match command:` ブロック内に限定。
- map_tool.gd のヘッダはコマンド一覧ではなく散文（使い方の例文）で、
  "godot" "keeps" 等を誤検出した → map はヘッダ抽出の対象外にし、
  コマンド名は `command ==` 比較から、説明は MCP 表から取る。
- ヘッダの説明抽出は、`[--flag]` のような値を持たないフラグが
  次の単語を「値」として食う問題と、JSON 引数の括弧深度を
  追跡して解決した（scatter / hd2d / pbr-assign 等で確認）。

## 検証

- Python テスト: `python3 -m unittest discover -s ai_loop/tests` で
  **15件全 pass**（新規 test_catalog.py 7件＋既存 test_replay_compare.py 8件）。
  突合テストの内容: (1) 新鮮な抽出とコミット済みカタログのエントリ
  集合が完全一致（生成漏れ・陳腐化の検出）、(2) 全エントリの source
  ファイルが実在し、MCP 名・CLI 名・クラス名が実装と一致、
  (3) 全 MCP ツールが自分の名前で検索にヒット、(4) CLI 実地検索。

- **C++ の変更はなし**。全テスト pass の判定は push 後の CI
  （uzu_verify: ビルド＋doctest＋`uzu.py selftest all`）で担保する。
