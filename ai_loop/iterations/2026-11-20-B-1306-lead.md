# B-1306 実証（『灯りの欠片』UI の UZUUI 作り直し）＋ B-1004 モバイル対応（タッチ操作）

担当: Muse (lead branch) / ブランチ `agent/b-1306-lead`、起点 ai-native a20f586300d。
BACKLOG の完了締めはリードが行う（本記録は実装と検証の報告）。

## テーマ選定: wafu

『灯りの欠片』は木造の家・鳥居・祠・提灯のある小さな村が舞台で、欠片集めで
昼→夕→夜へ光が移る。和紙の額縁・濃茶の縁・朱色のアクセントを持つ B-1307 の
`wafu` がそのまま世界観に合うため採用した。動きは同テーマの所作
（quart ease-out 0.35 秒、オーバーシュートなしの静かな開閉）に揃え、
UZUUIJuice の count_up / hover_pulse は収集の手応えとしてだけ足した。
比較対象の fantasy（金縁）や persona（斜め帯）は村の静けさに対して装飾が強い。

## 作り直した画面

- **タイトル**（title.gd + ui/title_ui.json → ui/title_ui.tscn）:
  オーバーレイを宣言的 UI 構築（B-1301、`uzu.py ui --spec`）の生成シーンに置換。
  和紙の額縁プラークに題字＋サブタイトル、ヒントも額縁チップ化。
  生成シーンはタップ開始を奪わないよう全 Control を MOUSE_FILTER_IGNORE にして重ねる。
  3D の UZUPicture と flat フォールバックは従来どおり。
- **HUD**（main.gd）: 素の Label 直書きを廃し、`UZUUI.create_world_theme("wafu")` を
  付けた UIRoot 配下に PanelContainer＋「灯りの欠片」ラベル＋
  `UZUUI.make_gauge(0, 3, 3)` の3セグメントゲージ＋「n / 3」＋目的文で構築。
  収集時は `UZUUIJuice.count_up`（ゲージの数え上げ）と `hover_pulse`（パネルの鼓動）。
- **プロンプト**: 画面下中央の額縁チップ（対象に応じて文言が変わる）。
- **会話**: `UZUUI.make_talk_window`（朱色の名前札＋和紙の会話窓＋▼送り印）。
  フォントはゲームのサブセットフォント 21px に上書き。
- **クリア画面**: 額縁パネル＋`apply_world_motion` の開閉。
- UZUUIWorld は `open_on_ready=false` で載せた。decorate() の自動オープンは
  非表示にしたい会話・クリア等の隠しパネルまで `set_visible(true)` してしまうためで、
  HUD だけ手動で開く。装飾（枠・質感・▼印）は全パネルに効いている。

## 会話の閉じ挙動の統一（意図的な挙動変更）

従来コードは最後の行を表示した後もパネルが閉じず、移動ブロックも行の残量依存だった。
新実装は `dialogue_open` で管理し、「開いている間は移動ブロック、最後の行の次の
インタラクトで世界観モーション付きで閉じる」に統一した。verify_playthrough は
NPC 会話を使わないため完走検証への影響はない。

## タッチ操作（B-1004）

- 追加ファイル: `virtual_stick.gd`（仮想スティック）、`touch_controls.gd`（配置と信号）。
- 表示条件（`_touch_ui_enabled()`）: 起動引数 `--uzu-touch-ui`、環境変数
  `UZU_TOUCH_UI=1`、`DisplayServer.is_touchscreen_available()` のいずれか。
  デスクトップ検証でも強制表示して確認できる。
- スティック: 左下 168x168、コード描画（半透明の和紙色ベース＋朱色ノブ）、
  デッドゾーン 0.22。ドラッグ中は `Input.action_press(action, strength)` で
  move_left/right/up/down をアナログ供給し、ゲーム側の `Input.get_vector`
  ポーリングと無変更で統合した。マウスでも操作できる（デスクトップ確認用）。
- インタラクトボタン: 右下 104x104、UZUUI テーマを継承。ラベルはプロンプトを
  鏡写しし（「話す」「欠片を拾う」等）、対象が無いときは「決定」＋半透明。
  FOCUS_NONE で Space/Enter（決定キー）を奪わない。押下は signal 経由で
  キーボードと同じ `_do_interact()` を呼ぶ。
- タイトルはタップでも開始できる（従来のタップ開始を維持）。

## 検証で見つけた落とし穴

Control の配置は「add_child の後に set_anchors_preset → position 設定」だと
アンカー基準の位置に落ちない（実測でスティックとボタンが画面外に出た）。
会話窓と同じく「追加前に anchors＋offset_* を直接設定する」方式に統一して解消。
プローブ（UI ツリーの rect ダンプ）で四隅の配置を数値確認してから撮影し直した。
