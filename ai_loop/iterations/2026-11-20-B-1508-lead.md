# B-1508 実証: 『灯りの欠片』の村を UZUWorldGen 生成で作り直す

担当: Muse (lead branch) / ブランチ `agent/b-1508-lead`、起点 ai-native a0b82de88a1。
BACKLOG の完了締めはリードが行う（本記録は実装と検証の報告）。

## 追補3件の扱い

1. **city の `ground` オプション（実装）**: `modules/uzu_worldgen/uzu_world_gen.cpp` の
   city_defs に `ground`（bool、既定 true）を追加。false では地面プレーンの
   メッシュ（"Ground"）と当たり（CityBody の "Ground" BoxShape）を生成しない。
   市の本体（街路・区画・建物・ベンチ・ランプ・街路樹）と NavigationMesh の
   ベイク（街路ベース）は従来どおり残る。既定 true なので既存の市の見た目と
   検証は不変。
2. **ベンチの当たり判定（実装）**: ベンチのメッシュ生成直後に、ベンチごとに
   凸型ボックス（半 extent 0.82 × 0.26、高さ 0.95。ナビベイクが切り取る
   フットプリントと同一）を CityBody に "Bench%d" として追加した。
   collision=false のときは従来どおり本体ごと無し。
3. **map_tool の NavigationRegion3D 保存（影響確認の結果、変更なし）**:
   agent/b-1507-lead の map_tool.gd には `_save_external` に
   NavigationRegion3D の navigation_mesh を外部 .res 化する2行がある。
   現行 ai-native の map_tool.gd で生成都市（village、seed 1）を保存し、
   CACHE_MODE_IGNORE で再読して実測したところ、**両保存モード
   （既定の外部保存／--inline）とも NavigationMesh は欠落しない**:
   生成時 652 ポリゴン／603 頂点 → 再読後も 652／603 で一致し、
   uzu_places メタも保持されていた。NavigationMesh は .tscn の
   サブリソースとしてそのまま保存されるため、2行は「外部ファイル化して
   整理する」選択肢であって欠落の修正ではない。よって map_tool.gd は
   変更しない。

新規単体テスト「City ground option and bench collision (B-1508)」
（test_uzu_world_gen.h）: resolve の既定で ground=true、既定生成で
Ground メッシュ＋形状あり、ベンチ形状数 == counts["benches"]、
ground=false で両方が消え、建物形状・ベンチ形状・places_connected は残る。

## 村の生成化（ai_loop/samples/hikari/main.gd）

手作りの地面プレーン・道・池ディスク・家3軒・木7本を撤去し、3枚の生成
マップの合成に置き換えた。祠とランタン、木箱、プレイヤー、NPC 3人、
欠片3つはゲームの成立条件として従来位置のまま手置き（y だけ地面から
決める）。spec は main.gd の static func（land_spec / pond_spec /
city_spec）に一元化し、compose_village.gd（新規）が同じ
build_generated_world を使って歩行チェック用シーンを組む。

- **Land（土台の自然）**: size 256 / cell 4 / seed 172 / height 2.2 /
  roughness 0.3 / water=false / trees 2.0 / rocks 0.4 / grass 6.0。
  水平化は「市タイル範囲（中心 (-21,-2) ±26.5）の地形最大値」で行う:
  1 m 刻みで測った最大値 1.614 に 0.05 の安全代を足し、holder の
  y = -1.664 とした（市は y=0）。散布（木・岩・草）はプレイヤーの
  移動クランプ＋2 m の内側だけ除去し、外側は景観として残した。
- **Pond（池の小マップ）**: size 32（自然マップの最小サイズ）/ cell 1 /
  seed 61 / height 0.7 / water_level 0.33 / roughness 0.35 /
  position (5.5, -0.37, 1.0)。この seed はマップ内の窪みが
  (9.5, 4.5) に来る配置で、水面 y = -0.139、合わせた障害物円は
  中心 (9.82, 4.59)・半径 3.21（マージン込み）。地形メッシュは市の
  東端 x=5.5 で切り取り、西側は Land が下に続く（height_at は解析式
  なので判定には影響しない、見た目だけの切断）。
- **City（村の市街）**: preset village / size 48 / block 16 / seed 1 /
  中心 (-21, -2) / **ground=false**。建物6・ベンチ4・街路樹26・
  実光源2。保護アンカー（ランタン・祠の柱・村長・スミレ・開始位置・
  木の欠片）への建物の最小 clearance は 4.82 m。なお seed 3 は
  スミレ (-4.6, 0.8) の上に建物が被ったため不採用（アンカー全点＋
  円判定＋places_connected で seed を選定した）。
- **CityFoundation（合成側の基礎）**: ground=false では街路に物理の床が
  無い（歩行チェックの物理 walker が街路から地形まで落ちて区画に
  引っかかった）。タイル範囲 53×53・厚さ 0.5・上面 -0.03 の基礎スラブ
  （メッシュ＋StaticBody）を合成側で足した。タイルの外では Land が
  そのまま地面になる。
- **障害物の導出（実行時）**: 建物とベンチは CityBody の凸形状から
  重心＋最大半径の円、街路樹は StreetTrees のインスタンス（r=0.35）、
  噴水は places.plaza から求めた中心（r は実効 3.2）、池は Land と
  Pond の合成高さ場から水際をフィット。プレイヤーと NPC・欠片の y は
  _ground_height（タイル内 = 0、外 = 2つの自然マップの高い方）に
  追随させる。池の欠片地点の合成高さは -0.114 で水面 (-0.139) より
  上（乾いている）。

シード選定の経緯（要約）: 池は当初「深さ 0.22 m の窪み」を探して
全滅した。滑らかな fbm では深い中心と乾いた岸は両立しないため、
浅い池（水深約 0.15 m）に緩めて seed 61 を得た。Land は当初
「欠片地点の高さ基準の平坦さ」で探して全滅し、「タイル内最大値で
水平化＋プレイヤーの地面追随」に設計を変えて seed 172 を得た。

## 検証

- **ビルド＋全テスト**: ベースライン（変更前）1574 件中 1572 pass /
  fail 2 件（[UDPServer]、サンドボックスの UDP 起因で無変更バイナリ
  でも再現する既知の環境起因）。変更後は **1575 件中 1573 pass /
  fail は同じ [UDPServer] 2 件のみ** / 3 skipped。新規テスト1件が増え、
  増えた分も pass。
- **完走検証**（verify_playthrough.py、種7で2回、判定条件は不変）:
  **passed**。チェックポイント順序 start→shard_1→shard_2→shard_3→
  lantern_lit、最終状態 shards=3 / cleared=true、juice_events =
  [pickup, pickup, pickup, lantern]、開始ハッシュは2回とも一致。
  リポジトリの verify_report.json も再生成して差し替えた: 開始
  ハッシュは従来と同一（1abc957f…）、shard_tree と lantern の
  チェックポイントハッシュだけが変わった（新しい障害物の間を
  抜けるため経路がわずかに違う。想定内）。
- **歩行検証**（uzu.py map walk、compose_village.gd で組んだ
  village.tscn）: **5/5 到達**（spawn から plaza / gate_north /
  gate_east / gate_south / gate_west、歩行距離は直線距離とほぼ一致）。
  前提条件: ナビメッシュは生成時に同期ベイクされ（652 ポリゴン）、
  保存・再読でも保持される（上記3の実測）。walker は物理ボディで、
  床は CityFoundation と各マップの当たりに依存する。
- **生成時間**: 村全体（Land＋Pond＋City＋ナビベイク）で **609 ms**
  （compose の実測、ヘッドレス、この VM）。
- **描画時間**（bench.py --render、VM のソフトウェア描画、主シーンを
  main.tscn にして 60 フレーム）: 生成版 wall 平均 9.1 ms / p95
  33.5 ms / 最悪 47.3 ms。手作り版は平均 6.6 ms / p95 22.8 ms /
  最悪 35.9 ms で、約1.4倍重い。**GPU での見た目と重さの判定は
  BACKLOG の指定どおりローカル RTX 4050 の確認待ち**（この数値は
  VM の lavapipe 参考値）。
- **スクリーンショット**: ai_loop/look_samples/hikari/b1508/ に
  before_top.png / before_game.png（手作り版、git HEAD の main.gd）と
  after_top.png / after_game.png（生成版）を同じ画角で保存した。
  生成版は瓦屋根の家・広場の噴水・街路樹・砂浜の池が読める。

## できなかったこと・残り

- GPU（RTX 4050）での見た目と重さは未確認。特に池の水面は
  ソフトウェア描画では白っぽく写る（after_top）ため、実 GPU での
  色味はローカル確認が要る。
- 市の西半分（広場・噴水を含む）はプレイヤーの移動クランプ
  （|x| ≤ 15.5）の外にあり、ゲームプレイからは到達できない
  （景観として見える範囲）。歩行チェックは市の places 全点で
  別途合格している。クランプ自体の変更はゲーム内容の変更になるため
  本項目では触っていない。
- 岸の南 (12.5, -12) 付近に、池マップの窪み由来の小さな水たまりが
  3点出る。ゲームプレイへの影響はないため許容した。
- B-1219 第2段（建物レシピ本体の置き換え、ORM/AO ベイク等）は
  範囲外として未着手。市は既存の第1段レシピのまま生成している。
