# B-307 状態ハッシュによる決定性検証 — claude (2026-11-18)

- ブランチ: ai-native に直接反映（リードの着手順。Wave 3 の推し1）。
- BACKLOG B-307: 固定の入力と固定の種で N フレーム実行し、ゲーム状態のハッシュを返す。変更の前後でハッシュを比べ、意図しない挙動の変化を機械で判定する。判定: 同じ条件で2回ならハッシュが一致し、サンプルで挙動を変える変更を入れるとハッシュが変わること。

## 内容（エンジン本体の変更なし）

- `ai_loop/selfplay/state_hash.gd`（新規。autoload `UZUStateHash`）:
  - 各物理フレームのゲームの処理の後に、N フレームごとに、宣言された状態の SHA-256 を取る。
  - 状態の宣言のしかた（ゲーム側）:
    - ノードをグループ `uzu_state` に入れる（`uzu_player` のプレイヤーも対象）。
    - 各ノードの transform（2D／3D）に加えて、`uzu_state()` メソッドが返す Dictionary か、メタデータ `uzu_state` に書いたプロパティ名の値を含める。
  - 並べ方: ノードのパス順。値は Godot のテキスト形式。同じ状態なら必ず同じハッシュになる。
  - 終了時に、ハッシュの一覧と最後の状態（中身）を書き出す。
- `uzu.py selfplay ... --hash-every 30 [--compare 前回の結果.json]`:
  - 結果に `state_hashes`（every・hashes・state）を足す。
  - `--compare` では、最初に食い違ったフレームと、終わりの状態の違い（ノードごとに前回と今回）を返す。食い違えば ok: false。
- サンプルゲーム: Main を `uzu_state` に入れ、`respawn_x`・`air`・`done`・`reached` を宣言した（宣言の手本）。

## 確認

- `uzu.py selftest selfplay` に追加した:
  - 同じ入力で2回: 20 時点すべてのハッシュが一致する（same: true）。
  - プレイヤーの速さを 4.0 → 4.2 に変えた版: 30 フレーム目で最初に食い違う。状態の違いも返る。
- 手で見た比較結果:
  - 速さを変えた版では、ジャンプの時機がずれて最初の穴に落ち続ける。
  - 終わりの状態の違いとして、done が false、reached が cp1 だけ、プレイヤーの位置が 1000 → 271.4 と返った（どこで何が変わったかが読める）。
- `uzu.py selftest` の engine／tools も ok。
- 全テスト: C++ の変更はないので、B-723／B-724 と同じバイナリで 1496/1496 pass。
